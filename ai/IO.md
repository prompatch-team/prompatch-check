# ai: 받는 값과 내보내는 값

`ai/` 폴더가 무엇을 받고 무엇을 내보내는지, 그리고 그 값이 왜 필요한지 적은 문서예요.

- 기준: 지금 `ai/` 코드와 연결 형식 0.3 (`contracts/conditions.schema.json`)
- "누가 쓰나"의 BE·FE는 `be/engine.py`, `fe/app.js` 기준이에요.

## 한눈에

```
가이드 원문 ──▶ [ai] ──▶ ① 조건 목록   (BE와 화면으로 가요)
(글 하나)        │   └─▶ ② 버린 목록   (개발·기록용. BE는 안 써요)
                 │
                 └─ AI API를 1번 불러요 (밖으로 나가는 요청은 이것뿐)
```

- 받는 것은 **가이드 원문 글 하나**예요.
- 내보내는 것은 **조건 목록**과 **버린 목록** 두 가지예요.
- AI는 조건을 뽑기만 해요. 위치, 번호, 셀 수 있는지는 코드가 정해요. 개수는 세지 않아요.

---

## 1. 받는 값

### 1-1. 함수로 부를 때

`doc, dropped = ai.extract.extract(guide, guide_id=..., cache_dir=..., llm=...)`

| 값 | 꼭 필요한가 | 무엇 | 왜 필요한가 |
| --- | --- | --- | --- |
| `guide` | 예 | 블로거가 붙여 넣은 가이드 원문 문자열 | 조건이 나오는 유일한 곳이에요. AI에게 보내는 글이면서, AI가 낸 인용이 진짜 있는지 확인하고 글자 위치를 계산하는 기준이에요 |
| `guide_id` | 아니오 | 가이드 이름 | 가이드를 여러 개 돌릴 때 결과가 어느 가이드 것인지 구분해요. 주면 결과에 그대로 실려요. 서버는 주지 않아요 |
| `cache_dir` | 아니오 | AI 결과를 저장할 폴더 | 개발 중에 같은 가이드로 AI를 다시 부르지 않으려고요 (비용, 그리고 결과가 부를 때마다 달라지는 것을 막기). 주지 않으면 파일에 아무것도 남기지 않아요. **서버는 주지 않아요.** 붙여 넣은 가이드를 남기지 않는 규칙 때문이에요 |
| `llm` | 아니오 | AI 대신 부를 함수 | 테스트에서 가짜 AI 응답을 넣으려고요. 자동 테스트는 API를 부르지 않아요 |

### 1-2. 환경 변수 (`.env`)

| 값 | 꼭 필요한가 | 무엇 | 왜 필요한가 |
| --- | --- | --- | --- |
| `ANTHROPIC_API_KEY` | 예 (AI를 부를 때) | AI API 키 | AI API를 부르려면 있어야 해요. 코드는 읽기만 하고 출력하지 않아요 |
| `PROMPATCH_MODEL` | 아니오 | 모델 이름 | 코드를 고치지 않고 모델을 바꾸려고요. 비우면 `claude-haiku-5-5` |

### 1-3. 명령어로 부를 때

`python -m ai <가이드 파일> [--call] [--out 파일] [--compare 파일] [--quiet]`

| 값 | 무엇 | 왜 필요한가 |
| --- | --- | --- |
| `<가이드 파일>` | 가이드 글 파일 경로 | 명령창에서는 글을 파일로 줘요. 파일 이름이 `guide_id`가 돼요 |
| `--call` | 캐시가 없을 때 AI를 1번 부름 | 실수로 AI를 부르지 않게 하려고요. 이 옵션이 없으면 캐시가 없을 때 멈춰요 |
| `--out 파일` | 조건 목록을 파일로 저장 | BE에 파일로 넘기거나 `validate.py`로 확인하려고요 |
| `--compare 파일` | 기준 조건 목록과 비교한 표를 보여 줌 | 정답과 얼마나 같은지 보려고요 (같음, 값이 다름, 놓침, 더 뽑음) |
| `--quiet` | 개수만 보여 줌 | 내용을 보면 안 되는 가이드(holdout)를 돌릴 때 써요 |

### 1-4. 받지 않는 것

| 받지 않는 것 | 왜 |
| --- | --- |
| 원고, 사진 수, 링크, 해시태그 | 세는 것은 BE의 일이에요. AI는 가이드만 봐요 |
| 주소(URL)로 된 가이드 | 서버는 네이버나 체험단 플랫폼에 접속하지 않아요. 붙여 넣은 글만 받아요 |
| temperature 같은 조절 값 | 지금 모델과 API 버전에서는 보낼 수 없어요. 그래서 같은 가이드라도 결과가 조금씩 달라질 수 있어요 |

## 2. AI API에 보내는 값

서버가 밖으로 보내는 요청은 이것 하나뿐이에요.

| 값 | 무엇 | 왜 필요한가 |
| --- | --- | --- |
| `model` | 모델 이름 | 어느 모델이 뽑을지 정해요 |
| `system` | 프롬프트 (`ai/prompt.py`의 `SYSTEM_PROMPT`) | 조건 종류 14가지와 뽑는 규칙을 알려 줘요 |
| `messages` | `<guide>` 태그로 감싼 가이드 글 | 가이드를 "지시"가 아니라 "자료"로만 읽게 하려고요. 가이드 안의 `</guide>`는 태그를 닫지 못하게 한 칸 띄워서 보내요 |
| `output_config.format` | 응답 모양 (`OUTPUT_SCHEMA`) | AI가 정해진 칸으로만 답하게 해서, 응답을 코드로 바로 읽으려고요 |
| `output_config.effort` | `medium` | 생각하는 정도예요 |
| `max_tokens` | 16000 | 응답 길이의 상한이에요. 넘어서 잘리면 오류로 처리해요 |

가이드 글 말고는 블로거의 정보를 보내지 않아요.

## 3. AI에게서 돌려받는 값 (가공 전)

이 값은 밖으로 나가지 않아요. 코드가 확인해서 4번의 조건 목록으로 바꿔요.

| 값 | 무엇 | 코드가 하는 일 |
| --- | --- | --- |
| `campaign_type` | `체험`, `기자단`, `모름` | "기자단"은 가이드에 근거 낱말이 있을 때만 받아요. `모름`은 `null`이 돼요 |
| `conditions[].type` | 조건 종류 | 14가지가 아니면 버려요 |
| `conditions[].label` | 짧은 이름 | 한 줄로 만들고 80자에서 잘라요 |
| `conditions[].quote` | 가이드에서 인용한 문장 | 원문에 있는지 찾아요. 없으면 조건을 버려요. 있으면 원문 글자와 위치로 바꿔요 |
| `conditions[].keywords`, `tags`, `terms`, `forbidden`, `phrase`, `allowed`, `url` | 기준이 되는 글자 값 | 가이드 원문에 그대로 있는지 확인해요. 없으면 조건을 버려요 |
| `conditions[].min` | 기준 숫자 | 인용 문장에 그 숫자가 안 보이면 `needs_review`를 달아요 |
| `conditions[].pick`, `scope`, `position`, `count_spaces` | 고르는 값 | 정해진 값이 아니면 기본값으로 바꿔요 |
| `conditions[].subject`, `after`, `category`, `what`, `question` | AI가 풀어 쓴 설명 | 한 줄로 만들고 120자에서 잘라요 |

**AI에게 묻지 않고 코드가 정하는 값**: `id`, `countable`, `start`, `end`, `platform`, `version`, `source`, `needs_review`, `unverified`. AI는 글자 위치를 정확히 세지 못하고, 응답을 그대로 믿을 수 없어서예요.

## 4. 내보내는 값 ①: 조건 목록

BE와 화면으로 가는 값이에요. `contracts/conditions.schema.json` 0.3을 따라요.

### 4-1. 맨 위

| 값 | 나올 수 있는 값 | 왜 필요한가 | 누가 쓰나 |
| --- | --- | --- | --- |
| `version` | 늘 `"0.3"` | 받는 쪽이 어떤 형식으로 읽을지 알아야 해요. 형식이 다르면 바로 오류로 잡혀요 | BE, `validate.py` |
| `guide_id` | 글자. 받았을 때만 있어요 | 어느 가이드의 결과인지 구분해요 | 개발, 측정 |
| `platform` | `"reviewplace"` 또는 `null` | 리뷰플레이스 모양의 가이드인지 알려 줘요. 이 모양일 때만 코드가 고정 칸을 직접 읽어요 | AI 코드, 화면 표시 |
| `campaign_type` | `"체험"`, `"기자단"`, `null` | 기자단은 직접 체험하지 않고 쓰는 글이라, 체험한 것처럼 쓴 표현을 따로 봐야 해요 (원칙 점검 p6) | BE |
| `conditions` | 조건 배열 (최대 60개) | 점검할 조건들이에요. 가이드에 나온 순서예요 | BE, 화면 |

### 4-2. 조건 하나

| 값 | 나올 수 있는 값 | 왜 필요한가 | 누가 쓰나 |
| --- | --- | --- | --- |
| `id` | `c1`, `c2`, … | 점검 결과가 어느 조건의 결과인지 짝을 지어요 (`condition_id`). 순서로 붙이는 번호라서, AI를 다시 부르면 같은 조건의 번호가 달라질 수 있어요 | BE, 화면 |
| `type` | 14가지 중 하나 (4-3) | BE가 어떤 방법으로 셀지 고르는 기준이에요 | BE |
| `label` | 짧은 이름 (80자까지) | 조건표와 결과 화면에 보여 줄 이름이에요 | 화면, BE(결과에 옮겨 적음) |
| `countable` | `true` / `false` | 코드로 셀 수 있는 조건인지예요. `false`면 BE는 세지 않고 판단 보류로 둬요 | BE |
| `params` | 종류마다 다름 (4-3) | 조건의 기준값이에요 (어떤 키워드를 몇 번, 몇 자 이상 등) | BE, 화면 |
| `guide_quote.text` | 가이드 원문에 있는 문장 | 이 조건이 가이드에 실제로 있다는 근거예요. 블로거가 "가이드 어디에 그렇게 써 있지?"를 바로 볼 수 있어요. 원문에 없으면 조건을 버려요 | 화면, 측정 |
| `guide_quote.start`, `end` | 원문의 글자 위치 (`end`는 포함하지 않음) | 가이드 안에서 그 문장의 자리를 가리켜요. 코드가 원문에서 찾아 계산해요 | 화면, 측정 |
| `extra_quotes` | `guide_quote`와 같은 모양의 목록. 있을 때만 | 같은 조건을 가이드 두 곳이 말할 때(구매 링크 줄과 리뷰어 미션의 "링크 삽입") 조건을 둘로 세지 않으면서 두 자리를 다 보여 주려고요 | 화면 |
| `source` | `"rule"`. 있을 때만 | 코드가 리뷰플레이스 고정 칸에서 직접 읽어 만든 조건이라는 표시예요. AI가 뽑은 조건에는 없어요. 지금은 판정에 쓰지 않고, 누가 만든 조건인지 기록으로 남겨요 | 측정, 개발 |

### 4-3. 종류별 `params`

| `type` | 뜻 | `params`의 값 | 왜 필요한가 |
| --- | --- | --- | --- |
| `title_keyword` | 제목에 키워드 | `keywords`(목록), `pick` | 제목에 넣을 키워드가 여러 개일 수 있어요. `pick`은 하나만 넣으면 되는지(`any`) 전부 넣어야 하는지(`each`)예요 |
| `keyword_count` | 키워드 N회 | `keywords`(목록), `min`, `pick`, `scope` | `min`은 몇 번 이상인지, `scope`는 제목·본문 중 어디서 셀지예요 (`title`, `body`, `title_and_body`) |
| `length` | 글자 수 | `min`, `count_spaces` | `min`은 몇 자 이상인지예요. `count_spaces`는 공백을 셀지인데(`true`/`false`), 가이드가 안 정했으면 `null`이에요. 공백 포함과 제외는 숫자가 크게 달라서 꼭 있어야 해요 |
| `photo_count` | 사진 수 | `min`, 있으면 `subject` | `subject`는 "매장 외관 사진"처럼 사진 내용이 정해진 경우예요. 내용은 코드가 볼 수 없어서 이때는 `countable: false`예요 |
| `video_count` | 동영상 수 | `min` | 몇 개 이상인지예요 |
| `link` | 링크 | `min`, `url` | `url`은 가이드가 정한 주소예요. 주소가 없으면(`null`) 개수만 봐요 |
| `map` | 지도 | `position` | `"bottom"`이면 글 하단에 있어야 하고, `null`이면 위치는 상관없어요 |
| `hashtag` | 해시태그 | `tags`(목록), `pick` | 태그는 `#`를 붙이고 띄어쓰기를 뺀 모양으로 맞춰요. 원고의 태그와 바로 비교하려고요 |
| `exact_phrase` | 정확한 표기 | `allowed`, `forbidden`(목록), `scope` | "이렇게 쓰고(`allowed`) 이렇게는 쓰지 마세요(`forbidden`)"를 담아요 |
| `banned_terms` | 금지어 | `terms`(목록), `category`, `scope` | `terms`는 찾을 단어예요. 단어 없이 "질병 이름"처럼 종류(`category`)만 있으면 코드로 못 찾아서 `countable: false`예요 |
| `required_phrase` | 필수 문구 | `phrase`, `scope`, 있으면 `after` | `phrase`는 꼭 넣을 문구예요. `after`는 "어느 문장 아래에"처럼 자리가 정해진 경우인데, 자리는 판단 보류예요 |
| `disclosure` | 대가성 문구 | `phrase`, `position` | `phrase`는 가이드가 정한 문구이고, 안 정했으면 `null`이에요. `position`이 `"top"`이면 글 첫 부분에 있어야 해요 |
| `outside_draft` | 원고 밖 조건 | `what` | 제출 기한처럼 원고만 봐서는 알 수 없는 조건이에요. 점검하지 않고 "원고 밖에서 확인할 것"으로 보여 주려고 따로 둬요 |
| `judgment` | 셀 수 없는 조건 | `question` | "다른 카페와 비교하지 않았는가"처럼 사람이 읽어야 아는 조건이에요. 블로거에게 물을 말을 담아요 |

- `min`은 `length`에서는 꼭 있어야 해요. 숫자가 없는 글자 수 조건은 버려요. 다른 종류에서는 AI가 숫자를 안 주면 1로 둬요.
- 키워드나 태그가 하나뿐이면 `pick`은 기본값으로 맞춰요 (키워드 `any`, 태그 `each`). 하나일 때는 뜻이 같아요.

### 4-4. `params`에 붙을 수 있는 표시

| 값 | 언제 붙나 | 왜 필요한가 | 누가 쓰나 |
| --- | --- | --- | --- |
| `needs_review: true` | 기준 숫자(2 이상)가 인용 문장에 아라비아 숫자로 안 보일 때. 예: 가이드에 "다섯 번" | 코드가 숫자를 확인하지 못했다는 표시예요. 조건을 버리면 블로거가 놓치니까 남기고, 조건표에서 숫자를 확인하게 해요 | 화면("숫자 확인 필요"), BE(결과 `note`에 적음) |
| `unverified: true` | AI가 낸 조건을 코드가 확인하지 못해 버렸을 때, 그 자리에 남기는 안내 조건 | 조건을 조용히 버리지 않으려고요. "조건 하나를 확인하지 못했어요. 가이드의 이 부분을 직접 봐 주세요"로 남겨요. `type`은 `judgment`이고, `guide_quote`는 코드가 찾은 가이드의 줄이에요 (못 찾으면 빈 글자, `start` = `end` = 0). AI가 쓴 글은 싣지 않아요 | 화면, BE(판단 보류로 셈) |

## 5. 내보내는 값 ②: 버린 목록

`extract()`가 돌려주는 두 번째 값이에요. BE의 점검에는 쓰지 않아요.

| 값 | 무엇 | 왜 필요한가 |
| --- | --- | --- |
| `code` | 버린 이유 코드 (아래 7가지) | 이유를 글이 아니라 정해진 코드로 세려고요. 로그와 측정에는 이 코드와 종류, 개수만 남겨요 |
| `reason` | 사람이 읽는 이유 | 개발할 때 왜 버렸는지 바로 보려고요 |
| `type` | AI가 낸 조건 종류 | 어떤 종류에서 자주 틀리는지 보려고요 |
| `label` | AI가 낸 이름 (200자까지) | 어떤 조건이었는지 알아보려고요 |
| `quote` | AI가 낸 인용 (200자까지) | 가이드의 어느 줄이었는지 찾아 안내 조건(`unverified`)을 만드는 데 써요 |

| 이유 코드 | 뜻 | 조건표에 안내를 남기나 |
| --- | --- | --- |
| `QUOTE_NOT_FOUND` | 인용 문구가 가이드 원문에 없음 | 남겨요 |
| `VALUE_NOT_IN_GUIDE` | 키워드·금지어·문구·태그·주소가 가이드 원문에 없음 | 남겨요 |
| `SCHEMA_INVALID` | 조건 모양이 아니거나, 모르는 종류거나, 꼭 있어야 하는 값이 비었음 | 남겨요 |
| `LIMIT_EXCEEDED` | 개수·길이·숫자가 상한을 넘음 | 남겨요 |
| `MISSION_KEYWORD_LINE` | 리뷰어 미션의 "키워드" 줄 (위의 키워드 조건과 같은 조건) | 안 남겨요 (일부러 합친 것) |
| `DUP_EXACT_PHRASE` | 표기 조건과 같은 문장에서 나온, 조건이 붙은 필수 문구 | 안 남겨요 (일부러 합친 것) |
| `DUPLICATE` | 똑같은 조건이 두 번 나옴 | 안 남겨요 (일부러 합친 것) |

버린 목록에는 가이드 글과 AI가 쓴 글이 들어 있어요. 그래서 로그에는 남기지 않아요. 로그에는 `drop_counts(dropped)`가 주는 "이유 코드:종류 → 개수"만 남겨요.

---

## 6. 그 밖에 나오는 값

| 값 | 무엇 | 왜 필요한가 |
| --- | --- | --- |
| `ExtractError` | AI를 부르지 못했거나 응답을 쓸 수 없을 때 나는 오류 | 받는 쪽이 "조건을 뽑지 못했어요"를 보여 줄 수 있게요. 메시지에 가이드 글은 넣지 않아요 |
| `last_usage` | 마지막 호출의 토큰 수 (`input_tokens`, `output_tokens`) | 비용을 가늠하려고요. 숫자뿐이에요 |
| 캐시 파일 (`ai/cache/*.json`) | `model`, `prompt`(프롬프트 지문), `raw`(AI 응답 원본) | 같은 가이드·모델·프롬프트면 AI를 다시 부르지 않으려고요. 저장소에 올리지 않아요 |
| 비교 표 (`--compare`) | 조건마다 같음 / 값이 다름 / 인용 범위가 다름 / 놓침 / 더 뽑음 | 기준 조건 목록과 얼마나 같은지 보려고요 |

`ExtractError`가 나는 경우: API 키가 맞지 않음, 모델 이름을 찾지 못함, 요청이 많아 막힘, API가 오류를 돌려줌, 연결하지 못함, AI가 거절함, 응답이 길어서 잘림, 응답이 JSON이 아님.

---

## 7. 상한

AI 응답은 믿을 수 없는 입력으로 다뤄요. 가이드에 숨긴 글로 AI가 조종당해도 조건 형식 밖의 결과가 나오지 않게 하려고 상한을 둬요.

| 대상 | 상한 | 넘으면 |
| --- | --- | --- |
| 조건 개수 | 60개 | 넘는 조건을 버려요 |
| 키워드·태그·금지어 개수 | 조건 하나에 30개 | 그 조건을 버려요 |
| 키워드·태그·금지어 하나의 길이 | 100자 | 그 조건을 버려요 |
| 필수 문구·표기·주소 하나의 길이 | 200자 | 그 조건을 버려요 |
| 인용 문구 길이 | 400자 | 그 조건을 버려요 |
| 이름(`label`) | 80자 | 잘라요 |
| 풀어 쓴 설명 | 120자 | 잘라요 |
| 기준 숫자 | 1,000,000 | 그 조건을 버려요 |
| 버린 목록 | 100개 | 그 뒤는 담지 않아요 |
| 안내 조건(`unverified`) | 가이드 하나에 10개 | 그 뒤는 만들지 않아요 |
