# ai: 가이드에서 조건 뽑기 (훈)

광고주 가이드 원문을 받아 `contracts/conditions.schema.json` 형식의 조건 목록을 내보내요.

- **입력**: 가이드 원문 문자열 (예시: `samples/guide-sample.md`)
- **출력**: 조건 목록 JSON (예시: `contracts/conditions.example.json`) + 버린 조건 목록
- **연결 ①** owner예요. BE가 받는 방법은 감자와 정해요. 지금은 함수(`ai.extract.extract(가이드)`)와 명령어(`python -m ai 가이드.md --out 조건.json`) 두 가지가 돼요.

## 파일

| 파일 | 하는 일 |
| --- | --- |
| `prompt.py` | 프롬프트(`SYSTEM_PROMPT`)와 LLM 응답 형식(`OUTPUT_SCHEMA`) |
| `extract.py` | AI API 부르기, 인용 확인, 위치 계산, 형식 맞추기, 캐시 |
| `test_extract.py` | 테스트. LLM 응답 자리에 가짜 응답을 넣어요. API를 부르지 않아요 |
| `test_security.py` | 보안 테스트. AI가 조종당해 엉뚱한 응답을 내도 조건 형식 밖의 결과가 안 나오는지 |
| `compare.py` | 뽑은 조건 목록을 기준 조건 목록과 비교 |
| `__main__.py` | 개발용 명령 |
| `cache/` | AI 결과 캐시. 저장소에 올라가지 않아요 |

## LLM이 하는 일과 코드가 하는 일

LLM은 가이드에서 조건을 뽑기만 해요. 개수는 세지 않아요. 나머지는 전부 코드가 해요.

| 코드가 확인하는 것 | 안 맞으면 |
| --- | --- |
| 인용 문구(`guide_quote.text`)가 가이드 원문에 그대로 있음 | 그 조건을 버려요 |
| 키워드·금지어·필수 문구·표기·태그·주소가 가이드 원문에 있음 | 그 조건을 버려요 |
| 기준 숫자(2 이상)가 인용 문구 안에 보임 | 조건은 남기고 `params.needs_review: true`를 달아요. 조건표에서 블로거가 확인해요 |
| 조건 종류가 `contracts`에 있는 14가지 중 하나이고 필요한 값이 있음 | 그 조건을 버려요 |

- 버린 조건은 이유와 함께 따로 돌려줘요 (`extract()`의 두 번째 값). 이유는 정해진 코드(`code`)로도 남겨요.

| 이유 코드 | 뜻 | 조건표에 안내를 남기나 |
| --- | --- | --- |
| `QUOTE_NOT_FOUND` | 인용 문구가 가이드 원문에 없음 | 남겨요 |
| `VALUE_NOT_IN_GUIDE` | 키워드·금지어·문구·태그·주소가 가이드 원문에 없음 | 남겨요 |
| `SCHEMA_INVALID` | 조건 모양이 아니거나, 모르는 종류거나, 꼭 있어야 하는 값이 비었음 | 남겨요 |
| `LIMIT_EXCEEDED` | 개수·길이·숫자가 상한을 넘음 | 남겨요 |
| `MISSION_KEYWORD_LINE` | 리뷰어 미션의 "키워드" 줄 (위의 키워드 조건과 같은 조건) | 안 남겨요 (일부러 합친 것) |
| `DUP_EXACT_PHRASE` | 표기 조건과 같은 문장에서 나온, 조건이 붙은 필수 문구 | 안 남겨요 (일부러 합친 것) |
| `DUPLICATE` | 똑같은 조건이 두 번 나옴 | 안 남겨요 (일부러 합친 것) |

- 기록(서버 로그, 측정 결과)에는 이유 코드와 조건 종류, 개수만 남겨요 (`drop_counts()`). 가이드 글과 AI가 쓴 글은 남기지 않아요.

## 조용히 버리지 않기

- 확인하지 못해 버린 조건(위 표에서 "남겨요")은 조건표에 조건 하나로 남겨요: 라벨 "조건 하나를 확인하지 못했어요", 물음 "가이드의 이 부분을 직접 봐 주세요", `params.unverified: true`, 종류는 `judgment`. 점검에서는 판단 보류로 세요.
- 안내에는 코드가 가이드에서 찾은 줄만 실어요. AI가 쓴 인용이나 라벨은 싣지 않아요. AI의 인용이 원문에 그대로 있으면 그 줄을, 없으면 가장 닮은 줄을 실어요. 닮았다고 보는 기준은 두 글자씩 묶었을 때 절반 이상 겹치는 것이에요 (우리 기준). 닮은 줄도 없으면 줄 없이 "가이드를 직접 다시 봐 주세요"라고만 해요.
- 같은 줄의 안내는 하나로 합치고, 가이드 하나에 10개까지만 남겨요.
- 리뷰플레이스 고정 칸의 줄에서 버린 조건은 안내하지 않아요. 그 칸은 코드가 직접 읽어요 (아래).

## 리뷰플레이스 고정 칸은 코드가 읽어요 (AI 결과의 안전망)

리뷰플레이스 모양의 가이드(`platform`이 `"reviewplace"`)에서만 해요. 다른 가이드에서는 아무것도 하지 않아요.

| 칸 | 코드가 읽는 모양 | 만드는 조건 |
| --- | --- | --- |
| 제목키워드 | 칸 이름, 쉼표로 나뉜 키워드 줄, "# 키워드 중 1개를 선택하여 제목(및 #태그)에 넣어주세요" 줄 | `title_keyword` (pick any). "태그" 말이 있으면 `hashtag`도 |
| 본문키워드 | 칸 이름, 키워드 줄, "# 키워드 중 1개를 선택하여 본문에 N번 이상 넣어주세요" 줄 | `keyword_count` (min N, pick any, scope body) |
| 리뷰어 미션 | 줄 전체가 "링크 삽입", "N자 이상", "N장 이상", "동영상 첨부" | `link`, `length`, `photo_count`, `video_count` |
| 리뷰 등록기간 | "리뷰 등록기간 …" 줄 | `outside_draft` |
| 공정위 대가성 문구 | 그 말이 든 줄. "상단", "첫 부분", "맨 위"가 있으면 position top | `disclosure` |

- AI 결과에 같은 조건(같은 종류, 같은 칸)이 없으면 코드가 만든 것을 넣고 `source: "rule"`로 표시해요.
- 있으면 AI 것을 쓰되, 기준값(키워드, 태그, 숫자, pick, scope)과 인용 줄은 코드가 읽은 것으로 맞춰요. 이 칸은 모양이 정해져 있어서 `needs_review`는 달지 않아요.
- 칸의 모양이 위와 다르면(예: 안내 줄이 없음) 코드는 그 칸을 만들지 않아요. AI 결과만 써요.

## temperature

- 코드는 temperature를 보내지 않아요 (모델 기본값). 0으로 고정할 수 없어요.
- 공식 문서: Claude Haiku 5.5에서는 `temperature`, `top_p`, `top_k`를 빼라고 해요. https://platform.claude.com/docs/en/models/haiku-5-5/migration-guide#remove-sampling-parameters
- 공식 문서: API 버전 `2026-10-21`에서는 이 값들을 보내면 어느 모델이든 400 오류가 나요. https://platform.claude.com/docs/en/api/versioning (Version history → 2026-10-21 → Messages API). 지금 쓰는 SDK(`anthropic` 2.14.0)가 보내는 버전이 `2026-10-21`이에요.
- "1만 받는다"는 문장은 공식 문서에서 찾지 못했어요 (확인 안 됨). 옛 API 버전(`2023-06-01`)에서 어떤 값을 받는지는 공식 문서에 적혀 있지 않았어요. 직접 보내서 시험하지도 않았어요.
- 그래서 결과가 부를 때마다 조금씩 달라져요.
- AI 응답은 믿을 수 없는 입력으로 다뤄요. 가이드 속 `</guide>`가 태그를 닫고 나오지 못하게 하고, 조건은 60개까지, 라벨은 80자, 풀어 쓴 설명은 120자, 키워드는 30개까지만 받아요. 넘으면 그 조건을 버리거나 잘라요.
- 위치(`start`, `end`)는 LLM에게 묻지 않고 코드가 원문에서 찾아 계산해요 (코드 포인트).
- 띄어쓰기·줄바꿈, 따옴표 종류(“ ” ‘ ’ ' "), 줄 맨 앞의 번호나 `# `만 다른 인용은 같은 인용으로 보고 원문 쪽 글자로 바로잡아요. 그 밖의 글자가 다르면 버려요. 줄 맨 앞의 `# `(리뷰플레이스 안내 줄)는 인용에 넣고, 줄 번호(`4. `)는 빼요.
- 리뷰어 미션의 "키워드" 한 줄을 조건으로 또 뽑으면 버려요. 위의 키워드 조건과 같은 조건이에요.
- 키워드나 태그가 하나뿐이면 `pick`을 기본값(`any` / `each`)으로 맞춰요. 하나일 때는 뜻이 같아요.
- `#태그`만 든 필수 문구(하나든 여러 개든)는 `hashtag` 조건으로 바꿔요.
- 해시태그는 띄어쓰기를 빼요. 키워드가 "솔내동 국수"면 태그는 `#솔내동국수`예요.
- 셀 수 있는지(`countable`), 가이드 형식(`platform`), 조건 번호(`id`, 가이드에 나온 순서)도 코드가 정해요.
- `platform`: "제목키워드", "본문키워드", "캠페인 안내", "리뷰어 미션" 칸이 2개 이상 있으면 `"reviewplace"`, 아니면 `null`.
- `campaign_type`: LLM이 골라요. "기자단"은 뒤의 점검이 달라지기 때문에 근거 낱말("기자단" 또는 "체험한 것처럼")이 가이드에 있을 때만 받고, 없으면 "체험"으로 둬요. LLM이 모른다고 한 경우만 `null`이에요.
- 필수 문구(`required_phrase`)가 표기 조건(`exact_phrase`)과 같은 가이드 문장에서 나왔고, 그 문장이 "언급할 경우", "언급 시", "쓸 때"처럼 조건이 붙은 문장이면 필수 문구를 버려요. 쓸 때의 표기 조건이지 꼭 넣으라는 조건이 아니에요. "반드시 X를 넣고 Y라고는 쓰지 마세요"처럼 조건 없이 둘 다 요구하면 둘 다 남겨요.
- `samples/private/` 아래의 가이드는 캐시를 `ai/cache/private/`에 따로 둬요. 둘 다 저장소에 올라가지 않아요 (`ai/.gitignore`, 맨 위 `.gitignore`의 `private/`).
- 주소가 있는 링크 조건과 주소 없는 링크 조건("링크 삽입")이 같이 나오면 하나로 합쳐요. 주소가 있는 쪽을 남기고, 다른 쪽의 가이드 원문은 `extra_quotes`에 둬요.
- 한글 숫자("다섯 번")는 코드가 못 알아봐서 `needs_review`가 붙어요.

## 혼자 개발하는 법

1. `samples/guide-sample.md`를 넣어 조건 목록을 뽑아요.
2. 뽑은 결과를 `python contracts/validate.py conditions 결과.json`으로 확인해요.
3. `criteria/sample-answer-key.md`의 조건 정답과 비교해요. 빠뜨린 조건, 지어낸 조건이 없어야 해요.

## 지킬 것

- 가이드에 없는 조건은 만들지 않아요. 조건마다 `guide_quote`에 원문과 위치를 남겨요.
- 셀 수 있는 조건도 개수는 세지 않아요. 기준값만 뽑고 세는 건 BE가 해요.
- API 키는 `.env`의 `ANTHROPIC_API_KEY`에서 읽어요. 코드는 값을 읽기만 하고 출력하지 않아요.
- 서버에서는 `extract(가이드)`를 `cache_dir` 없이 불러요. 그러면 가이드 글이 파일에 남지 않아요. 캐시는 개발용 명령에서만 써요.
- `ANTHROPIC_LOG` 환경 변수를 켜면 SDK가 요청 내용을 로그에 남겨요. 서버에서는 켜지 않아요.

## 여기에 적어 주세요

- 쓰는 언어와 라이브러리: 파이썬 3, `anthropic` SDK (`pip install -r ai/requirements.txt`). 테스트는 `unittest`, 형식 확인 테스트에만 `jsonschema`.
- 실행 방법: 저장소 맨 위 폴더에서 실행해요.
  - 패키지는 가상환경에 설치해요: `pip install -r ai/requirements.txt`
  - 테스트 (API를 부르지 않음): `python -m unittest ai.test_extract ai.test_security`. `be`·`criteria` 쪽 코드가 있어야 도는 테스트 2개는 건너뛰어요.
  - 조건 뽑기: `python -m ai samples/guide-sample.md`
    - 캐시에 있으면 캐시를 써요. 없으면 멈추고 알려 줘요.
    - `--call`을 붙였을 때만 AI API를 1번 불러요. 결과는 `ai/cache/`에 저장돼서, 같은 가이드·모델·프롬프트면 다시 부르지 않아요.
    - `--out 결과.json`으로 파일에 저장할 수 있어요.
    - `--compare contracts/conditions.example.json`을 붙이면 기준 조건 목록과 비교한 표를 보여 줘요. 번호가 아니라 종류와 인용 문구로 짝을 지어요. 원고 밖 조건(`outside_draft`)은 세지 않아요.
- 쓰는 모델과 프롬프트 위치: 기본 `claude-haiku-5-5` (개발 중 작은 모델). `.env`의 `PROMPATCH_MODEL`로 바꿔요. 프롬프트는 `ai/prompt.py`.
