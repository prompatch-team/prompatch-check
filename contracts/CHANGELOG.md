# 연결 형식이 바뀐 기록

새 판이 위에 있어요. 형식을 바꾸면 스키마·예시·`version`을 함께 고치고 여기에 한 줄씩 적어요.

## 0.4 (2026-11-28)

강남맛집 키워드 규칙을 확정하면서(실제 글 검수 통과로 확인) 두 가지를 더했어요. 세 형식의 `version`은 `"0.4"`예요. 0.3으로 만든 값은 `version`만 바꾸면 그대로 통과해요.

| 무엇 | 뜻 |
| --- | --- |
| 점검 요청 `tag_area` (없어도 돼요) | 맨 아래 태그 칸의 태그만 따로 보내요 |
| `keyword_count`의 `scope: "title_body_tags"` | 제목 + 본문(해시태그 포함) + 태그 칸을 합쳐 정확히 같은 낱말만 세요. 강남맛집만 써요. 다른 업체는 그대로(태그 칸 뺌) |
| `map`의 `strict: false` | 위치가 다르면 빠짐 대신 판단 보류("확인해 주세요"). 강남맛집만 써요 |

## 0.3 (2026-11-28)

지금 실제로 돌아가는 점검이 주고받는 값을 전부 담았어요. 세 형식의 `version`은 `"0.3"`으로 고정이에요.

### 조건 목록: 0.2에서 바뀐 것

스키마는 `version` 값만 달라요. 0.2로 만든 조건 목록은 `version`만 바꾸면 그대로 통과해요. 아래는 `params`에 쓰는 값과 판정 방법이 늘어난 것이에요 (README의 표).

| 무엇 | 뜻 |
| --- | --- |
| `keyword_count`의 `pick: "sum"` | 고른 키워드의 합계로 세요 |
| `keyword_count`, `title_keyword`의 `pick: "both"` | 가이드가 "전부"인지 "하나 이상"인지 말하지 않았을 때 두 해석을 같이 적어요. 다르면 판단 보류 |
| `keyword_count`의 `params.free` | 블로거가 직접 고르는 자율 키워드. `keywords`가 비어 있어도 돼요 |
| `photo_count`의 `max`, `include_video` | 사진 상한, 동영상도 장수에 넣는 가이드 |
| `disclosure` | 가이드가 문구를 정하지 않았으면 맨 위 체험단 배너도 대가성 표시로 봐요 |
| 조건 뽑기 주소의 `ai`, `form`, `dropped` | 조건 목록을 감싸서 주고받는 값을 README에 적었어요. 가이드 형식 네 가지(`reviewplace`, `revu`, `gangnam`, `reviewnote`)는 `form`으로 가요 |

정하지 않은 것: 조건 목록의 `platform`은 지금도 `"reviewplace"` 아니면 `null`이에요. `form`의 네 값을 `platform`으로 옮길지는 AI 쪽 PR에서 정해요.

### 점검 요청: 0.1 초안에서 바뀐 것

0.2 판은 팀 저장소에 올라간 적이 없어서 0.1 초안과 비교해요.

| 무엇 | 0.1 초안 | 0.3 |
| --- | --- | --- |
| `guide_text` | 꼭 있어야 함 | 없앰. 가이드는 조건 뽑기 주소로만 보내요 |
| `input_mode`, `counts_source` | 없음 | 꼭 있어야 함. 서식을 읽었는지, 숫자를 누가 셌는지 |
| `title` | 없음 | 제목. 모르면 `null` |
| `video_count`, `links`, `hashtags`, `media` | 없음 | 서식에서 읽은 동영상 수, 링크, 해시태그, 미디어 자리 |
| `captions`, `count_captions` | 없음 | 사진 설명 자리와, 글자 수에 넣을지 |
| `banner_count`, `banner_top` | 없음 | 체험단 배너 수와 맨 위 배너 |
| `photo_count`, `has_map` | 없어도 됨 | 그대로. 모르면 `null` |

### 점검 결과: 0.1 초안에서 바뀐 것

| 무엇 | 0.1 초안 | 0.3 |
| --- | --- | --- |
| `principles` | 없음 | 꼭 있어야 함. 원칙 점검 p1~p7 (`rule_id`, `label`, `status`, `basis`, `note`, `draft_spans`) |

### 세는 법이 바뀐 것

| 무엇 | 0.1 초안 (main) | 0.3 |
| --- | --- | --- |
| 글자 위치 | 단위를 정하지 않음 | 코드 포인트 (이모지 1개 = 1글자) |
| 공백 포함 글자 수 | 줄바꿈도 1글자 | 문단 안의 글자와 띄어쓰기만. 줄바꿈·빈 줄·줄 앞뒤 공백은 세지 않아요 |
| 가이드가 공백 기준을 안 정했을 때 | 공백 제외로 판정 | 공백 포함으로 판정 (둘 다 `note`에) |
| 본문 해시태그 안의 키워드 | 구분 없이 셈 | 세되, `note`에 "본문 글 N번 + 해시태그 M번"으로 나눠 적어요 |
| 편집 화면 줄, 보기 화면에서 딸려 온 줄, 숨은 문자 | 그대로 셈 | 빼고 세요 |
| 같은 주소의 링크 | 링크 조건이 없었음 | 1개로 세요 |

## 0.2 (2026-11-26)

조건 목록만 바꿨어요.

- 조건 종류 6가지 → 14가지 (제목 키워드, 동영상, 링크, 해시태그, 정확한 표기, 금지어, 필수 문구, 원고 밖 조건 추가)
- `keyword_count`: `keyword`(하나) → `keywords`(목록) + `pick` + `scope`
- 맨 위에 `platform`, `campaign_type`. 조건에 `extra_quotes`, `source`, `params.needs_review`, `params.unverified`
